屏蔽 YouTube 短视频中的广告：仅屏蔽信息流广告，不屏蔽视频广告

YouTube 短视频中的广告是原生信息流单元，插入在您滚动浏览的垂直视频之间，而非嵌入播放器内部的前贴片广告。它们属于页面元素，而非按计划插入的播放器中断，因此通过样式过滤（CSS 和 DOM 规则）来隐藏广告容器。覆盖效果真实存在，但当广告格式发生变化时可能存在局限性。

短视频广告与视频广告是两种截然不同的广告形式

当预广告在普通视频前播放时，播放器会请求该广告、播放它，然后继续播放您的视频。而短视频则不同：当您在信息流中滑动浏览时，信息流中的部分内容本身就是广告。它们看起来像短视频，滚动方式也与短视频一致，并且属于同一信息流响应的一部分——它们并非由播放器单独安排的广告插播时段。

这一区别决定了整个屏蔽策略。播放器级工具（如计划移除、播放加速）在此处无从下手，因为从不安排任何中断。

为什么“ cosmetic filtering（视觉过滤）”是处理信息流广告的正确工具

信息流广告是一种具有可预测结构的页面元素：包含容器、如“赞助”标记之类的标签，以及广告单元特有的渲染组件。视觉过滤通过使用 CSS 选择器和 DOM 规则匹配这些结构，在广告容器渲染前或渲染过程中将其隐藏，从而确保信息流条目始终不可见。

“ cosmetic filtering” 在信息流中能做什么，不能做什么

功能说明：隐藏结构匹配所选选择器的广告单元，并移除与之配套的“赞助”标签和覆盖图块。在格式稳定的页面上，这一方式可靠且高效——无需等待，无需倒计时，广告根本不会出现在您的滑动流中。

它无法做到：保证覆盖尚未发布的格式。如果平台更改了信息流广告单元的结构，选择器将不再匹配，直到被更新。这是每种视觉遮蔽类方案固有的局限性，适用于所有广告屏蔽工具，而不仅限于某一款。

为什么仅靠网络层屏蔽无法覆盖短视频（Shorts）

在 DNS 或网络层面屏蔽广告网络（参见 基于 DNS 的 Android 屏蔽）可阻止对已知广告服务器的请求。但视频平台中的信息流广告通常与内容信息流本身共用相同的域名和请求路径，因此若通过网络过滤器将其屏蔽，将导致整个信息流失效。正因如此，实际的屏蔽工作需在浏览器中、DOM 层面进行，通过结构差异区分广告单元与内容单元。

常见问题

YouTube Shorts 中的广告与普通视频广告相同吗？

不。短视频广告是原生信息流单元，插入在您滚动时的竖屏视频之间；普通视频广告则是播放器内按计划插入的广告时段。不同的投放方式意味着不同的拦截技术。

那么，Shorts 广告是如何被屏蔽的呢？

通过视觉过滤：采用 CSS 和 DOM 规则识别信息流中广告容器的结构，并在渲染前将其隐藏。视频广告调度层无从下手，因为信息流中并未安排任何广告插播。

所有短视频广告都能被隐藏吗？

大多数当前格式确实如此，但并未附带承诺：如果平台推出新的信息流广告结构，选择器将无法匹配，直到它们被更新为止。视觉覆盖仅适用于现有格式。

为什么 DNS 层广告拦截无法移除 Shorts 广告？

因为信息流广告通常通过与内容信息流相同的域名进行投放。若网络过滤器拦截了这些请求，将导致整个信息流无法正常显示。唯有浏览器内过滤可通过页面结构实现二者的分离。
